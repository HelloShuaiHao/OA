# Linus 说人话：AgentX 真实场景用户流程

## 前言

别跟我扯什么"数字化转型"、"AI 赋能"这些虚的。我就告诉你，按照这个方案，**真实的人**在**真实的场景**下，到底怎么用这个系统。

不是 PPT 上的流程图，是**你明天上班就能用的东西**。

---

## 角色定义

先说清楚有哪些人：

1. **IT 管理员（老王）** - 负责搭建和配置系统
2. **部门经理（张经理）** - 销售部经理，要管理数字员工
3. **普通员工（小李）** - 销售部员工，要用数字员工干活
4. **财务（老陈）** - 财务部，要审批报销
5. **HR（小美）** - 人事部，要处理请假

## 场景 1：请假审批（最基础的场景）

### 第一次搭建（IT 管理员老王）

**老王的任务：给公司搭一个请假审批助手**

#### 步骤 1：创建流程（在 OA 流程管理里）

老王打开 OA → 流程管理 → 创建流程

**方式 A：用自然语言（推荐）**
```
老王输入：
"员工提交请假，如果请假天数小于等于 2 天，自动通过。
如果大于 2 天，需要直属上级审批。
如果大于 5 天，还需要部门负责人审批。"

系统：
[生成流程图]

老王看了一眼流程图，觉得没问题，点击保存。
流程名称：请假审批流程（标准）
```

**方式 B：用模板（更快）**
```
老王：选择模板 → 请假审批模板 → 修改参数 → 保存
```

#### 步骤 2：创建数字员工

老王打开 AgentX 管理 → 创建数字员工

```
步骤 1：基本信息
- 名称：请假审批助手
- 部门：人事部
- 头像：选个机器人图标

步骤 2：选择模板
- 选择：请假审批助手模板

步骤 3：配置能力
- ☑ 查看待审批任务
- ☑ 审批请假申请
- ☑ 发送通知

步骤 4：关联流程
- ☑ 请假审批流程（标准）

步骤 5：激活
- 点击"激活并发布"
```

**搞定！老王花了 5 分钟。**

---

### 日常使用（普通员工小李）

**小李要请 3 天假**

#### 方式 A：在 OA 里提交（传统方式）

```
小李：
1. 打开 OA → 请假申请 → 填写表单
   - 请假类型：年假
   - 开始日期：2026-03-25
   - 结束日期：2026-03-27
   - 请假天数：3 天
   - 理由：回老家办事

2. 提交

系统：
- 创建请假单
- 触发流程：请假审批流程（标准）
- 因为 3 天 > 2 天，流程走到"直属上级审批"节点
- 通知张经理

张经理：
- 收到通知：小李请假 3 天
- 打开审批页面，看到请假详情
- 点击"同意"

小李：
- 收到通知：请假已通过
```

**这就是标准流程，没有 AI 介入。**

#### 方式 B：通过 Telegram 跟 AI 聊（新方式）

**前提：小李已经绑定了 Telegram 账号**

```
小李（在 Telegram）：
"我要请 3 天假，3 月 25 到 27 号，回老家办事"

"好的，我帮你提交请假申请。

请假信息：
- 类型：年假
- 日期：2026-03-25 至 2026-03-27
- 天数：3 天
- 理由：回老家办事

确认提交吗？"

小李：
"确认"

请假审批助手：
"已提交。因为请假天数大于 2 天，需要你的直属上级张经理审批。
我已经通知他了，审批结果会通知你。"

（10 分钟后）

请假审批助手：
"好消息！张经理已经批准了你的请假申请。祝你旅途愉快！"
```

**小李全程在 Telegram 聊天，没打开 OA。**

## 总结：关键点

### 1. 灵活性

- **不只是审批**：ERP、客服、数据分析、协作，什么场景都能做
- **流程自定义**：用自然语言描述，AI 生成流程
- **多 Agent 协作**：复杂场景自动协调

### 2. 用户友好

- **普通员工**：通过 Telegram/企微聊天，不用打开 OA
- **管理员**：可视化配置，不用写代码
- **IT 人员**：复用现有系统，不用重复造轮子

### 3. 真实可用

- **不是 Demo**：这些场景都是真实企业需求
- **不是 PPT**：每个流程都能落地
- **不是未来**：现在就能实现
