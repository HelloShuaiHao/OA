# 20260322 解决方案（AgentX × OA × OpenFang）

## 1. 目标与硬约束

### 业务目标
- 让企业在 OA 内完成 Agent 的全生命周期管理（创建、授权、发布、监控、审计）。
- 让 Agent 能自动处理可自动化流程，并在需要时可靠拉人介入。
- 支持一个 Agent 绑定多个业务流程场景，并按规则自动路由。

### 硬约束（必须满足）
- 不允许业务用户输入 `workflow_id`、`scenario_code`、JSON 等技术字段。
- 不要求业务用户进入 OpenFang 做配置。
- OA 是治理与审批真相源；OpenFang 是运行时执行引擎。

## 2. 现状复杂点（问题本质）

- 目前“场景到 workflow”的映射暴露了技术心智，业务用户难理解。
- 用户难判断“哪个流程由哪个 Agent 接手”，路由关系不透明。
- 人工介入（谁能介入、何时介入）缺少统一配置入口。
- Channel（如 Telegram）配置与用户身份绑定链路还未产品化。

## 3. 总体方案（产品形态）

## 3.1 OA 成为唯一控制台
- 在 OA 提供 **Agent 管理中心**，OpenFang 隐藏在系统内部。
- OpenFang 仅由平台管理员维护连接，不向业务用户暴露技术参数。

## 3.2 配置分层（把技术字段关进后台）
- 业务层（给业务管理员）：
  - 业务场景名称（如：请假审批助手）
  - 适用流程（从 OA 流程下拉选择）
  - 自动审批策略（如：<=2 天自动通过）
  - 人工介入策略（触发条件、审批角色）
- 平台层（给平台管理员，默认一次配置）：
  - 场景到 OpenFang workflow 映射
  - Tool/Skill 白名单
  - 运行参数与回调策略

## 3.3 三个“自动化翻译器”
- 流程翻译器：`OA流程定义/实例 -> 内部场景键`
- 路由翻译器：`内部场景键 -> OpenFang workflow`
- 身份翻译器：`Channel账号 -> OA用户ID`

> 业务用户只看“中文名与规则”，不看任何 ID。

## 4. 针对 7 个问题的落地解法

## 4.1 Agent 在 OA 创建与管理
- 提供 OA 页面：Agent 列表、启停、版本、负责人、生效范围。
- 发布动作一键完成：OA 下发配置到 OpenFang（用户无感）。

## 4.2 Skill / 权限 / Tool 管理
- OA 中用“能力包”抽象（如：审批查询、审批执行、通知发送）。
- 技术上的 Tool 名称在后台映射，不暴露给业务用户。
- 权限采用“角色 + 能力包 + 数据范围”三维授权。

## 4.3 OA 流程如何对齐到 Agent
- 在 OA 选择“流程定义”后，系统自动生成/绑定内部场景。
- 同一个 Agent 可挂多个流程场景（多对多）。
- 运行时按“流程定义 + 条件规则”自动选择执行路径。

## 4.4 与人的交互定义
- 交互规则放在 OA 的“介入策略”里，不放在 workflow JSON。
- 介入人必须从 OA 现有组织/角色中选择，禁止自由文本填人。

## 4.5 无需人工介入场景
- 支持“纯自动模式”：满足规则直接闭环，无人工节点。
- 仍保留审计与可回放，确保事后可追踪。

## 4.6 Channel 接入
- Channel 连接入口统一在 OA（Telegram/企业微信/邮件等）。
- OA 存连接配置，OpenFang 作为执行通道。
- 后续新增渠道时对业务层无心智变化。

## 4.7 谁能和 Agent 交互（身份治理）
- 首次外部交互用户进入“待认证池”。
- 认证后绑定到 OA 用户（员工/外部联系人）。
- OA 用户中心可查看“用户-渠道账号”绑定关系与历史交互。

## 5. 关键数据模型（对业务可见）

- Agent（数字员工）
- 业务场景（中文名）
- 流程绑定（选择 OA 流程）
- 介入策略（条件 + 角色）
- 渠道绑定（账号映射）
- 运行记录（任务、审批、审计）

> `workflow_id / scenario_code / json` 仅保留在平台层，不给业务用户输入。

## 6. 推荐实施顺序（分阶段）

### Phase A（先降复杂度，最快提升体验）
- OA 上线 Agent 管理中心（隐藏技术字段）。
- 场景配置改为“选流程定义 + 选规则”，后台自动映射 workflow。
- 介入策略改为“选角色/人”，不允许手填。

### Phase B（打通身份与渠道）
- Channel 接入配置收口到 OA。
- 上线账号绑定与首次认证流程（外部账号 -> OA 用户）。

### Phase C（规模化运营）
- 模板化：预置常见业务场景（请假/报销/采购）。
- 版本化：Agent 配置灰度发布、回滚、AB 策略。

## 7. 验收标准（面向体验）

- 业务管理员配置流程时，页面不出现任何技术 ID/JSON 输入框。
- 新建 Agent 并绑定“请假审批”场景 <= 3 分钟可完成。
- 用户从提交请假到自动审批/人工介入链路可完整回放。
- 外部渠道用户可被识别并绑定 OA 身份。
- 关键动作（授权、审批、回调）全链路可审计。

## 8. 最终结论

当前方向是正确的：`OA管治理 + OpenFang管运行 + AgentX做桥接`。  
下一步的重点不是继续堆功能，而是 **把技术概念彻底从业务界面下沉**，把“能跑”升级为“好用、可推广、可规模化运营”。
