# 复用现有 Workflow 的重新设计

## 问题分析

当前方案的问题：
- 想在 AgentX 中重新做一套 Workflow 管理
- 与 OA 现有的 Flowable 流程管理功能重复
- 浪费开发资源，增加系统复杂度

## 正确的做法：复用 OA 现有的 Workflow

### 1. OA 现有的 Workflow 能力

**Flowable 已经提供：**
- ✅ 可视化流程设计器（BPMN 2.0）
- ✅ 流程定义管理
- ✅ 流程实例执行
- ✅ 任务管理
- ✅ 审批节点
- ✅ 条件判断
- ✅ 并行网关

**我们需要做的：**
- 让 Agent 能够理解和执行这些流程
- 在流程中增加 Agent 可用的节点类型
- 建立 OA Workflow 与 OpenFang 的桥接

### 2. 重新设计的架构

```
┌─────────────────────────────────────────────────┐
│           OA 流程管理（Flowable）                │
│  - 可视化流程设计器                              │
│  - 流程定义管理                                  │
│  - 已有的审批、判断、通知等节点                  │
├─────────────────────────────────────────────────┤
│           AgentX 扩展节点（新增）                │
│  - AI 决策节点                                   │
│  - Tool 调用节点                                 │
│  - 数据查询节点                                  │
│  - 外部 API 调用节点                             │
├─────────────────────────────────────────────────┤
│         AgentX 流程执行引擎（桥接层）            │
│  - 监听 Flowable 流程事件                        │
│  - 执行 AgentX 扩展节点                          │
│  - 调用 OpenFang（如果需要）                     │
└─────────────────────────────────────────────────┘
```

### 3. 具体实现方案

#### 方案 A：扩展 Flowable 节点（推荐）

**在 Flowable 流程设计器中增加 AgentX 节点：**

```xml
<!-- 示例：AI 决策节点 -->
<serviceTask id="aiDecision" name="AI 决策"
             flowable:class="cn.iocoder.yudao.module.agentx.flowable.AiDecisionDelegate">
  <extensionElements>
    <flowable:field name="prompt">
      <flowable:string>根据请假天数判断是否需要审批</flowable:string>
    </flowable:field>
    <flowable:field name="inputVariables">
      <flowable:string>leaveDays,leaveType</flowable:string>
    </flowable:field>
  </extensionElements>
</serviceTask>

<!-- 示例：Tool 调用节点 -->
<serviceTask id="callTool" name="调用 Tool"
             flowable:class="cn.iocoder.yudao.module.agentx.flowable.ToolCallDelegate">
  <extensionElements>
    <flowable:field name="toolName">
      <flowable:string>bpm_query_tasks</flowable:string>
    </flowable:field>
    <flowable:field name="params">
      <flowable:string>{"userId": "${userId}"}</flowable:string>
    </flowable:field>
  </extensionElements>
</serviceTask>
```

**在流程设计器中显示为：**

### 4. Agent 与 Flowable 流程的关联

**数据库设计：**

```sql
-- Agent 与 Flowable 流程定义的关联
CREATE TABLE agentx_agent_process (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    tenant_id BIGINT NOT NULL,
    agent_id BIGINT NOT NULL,
    process_definition_key VARCHAR(128) NOT NULL,  -- Flowable 流程定义 key
    process_name VARCHAR(128),
    selection_mode VARCHAR(32),  -- rule, auto
    selection_rules JSON,
    enabled TINYINT DEFAULT 1,
    created_time DATETIME NOT NULL,
    INDEX idx_agent (tenant_id, agent_id)
);
```

### 5. 执行流程

**当 Agent 需要执行流程时：**

```java
// 1. Agent 选择合适的流程
String processKey = selectProcess(agentId, taskContext);

// 2. 启动 Flowable 流程实例
ProcessInstance processInstance = runtimeService
    .startProcessInstanceByKey(processKey, variables);

// 3. Flowable 执行流程
// - 遇到标准节点（用户任务、网关等），Flowable 自己处理
// - 遇到 AgentX 扩展节点，调用 AgentX 的 Delegate

// 4. AgentX Delegate 处理扩展节点
public class AiDecisionDelegate implements JavaDelegate {
    @Override
    public void execute(DelegateExecution execution) {
        // 调用 LLM 做决策
        String decision = llmService.decide(prompt, variables);
        execution.setVariable("decision", decision);
    }
}

// 5. 流程完成后，通知 Agent
```

### 6. 与 OpenFang 的关系

**重新定位 OpenFang 的角色：**

```
之前的设计：
OpenFang 是主要的流程执行引擎
OA 只是配置和监控

现在的设计：
Flowable 是主要的流程执行引擎（OA 已有）
OpenFang 作为可选的 AI 能力增强
- 复杂的 AI 推理
- 多 Agent 协作
- 长时间运行的 AI 任务
```

**什么时候用 Flowable，什么时候用 OpenFang：**

| 场景 | 使用 | 理由 |
|------|------|------|
| 标准审批流程 | Flowable | OA 已有，成熟稳定 |
| 带 AI 决策的流程 | Flowable + AgentX 扩展节点 | 复用现有基础 |
| 复杂 AI 推理 | OpenFang | 需要强大的 AI 能力 |
| 多 Agent 协作 | OpenFang | Flowable 不支持 |
| 长时间 AI 任务 | OpenFang | 需要状态管理 |

### 8. 实施步骤

**Phase 1：扩展 Flowable 节点**
1. 开发 AgentX 扩展节点（AI 决策、Tool 调用等）
2. 在流程设计器中注册这些节点
3. 编写节点的 Delegate 实现

**Phase 2：AI 辅助生成**
1. 开发自然语言转 BPMN 的功能
2. 集成到流程创建界面
3. 支持生成后在设计器中调整

**Phase 3：Agent 关联流程**
1. 开发 Agent 与流程的关联管理
2. 实现流程选择策略（规则/AI）
3. 实现流程执行监控

### 9. 优势

**复用现有基础：**
- ✅ 不重复造轮子
- ✅ 降低开发成本
- ✅ 用户学习成本低（已熟悉 Flowable）
- ✅ 成熟稳定（Flowable 久经考验）

**增强而非替代：**
- ✅ 在现有基础上增加 AI 能力
- ✅ 保持向后兼容
- ✅ 渐进式升级

**清晰的职责分工：**
- Flowable：流程编排和执行
- AgentX：AI 能力和 Tool 调用
- OpenFang：复杂 AI 场景（可选）

### 10. 总结

**不要做：**
- ❌ 重新开发一套 Workflow 管理
- ❌ 替代 Flowable
- ❌ 让用户学习新的流程设计方式

**应该做：**
- ✅ 扩展 Flowable 节点，增加 AI 能力
- ✅ 提供 AI 辅助生成，降低设计门槛
- ✅ 让 Agent 能够执行 Flowable 流程
- ✅ 复用现有的流程管理基础设施

**关键原则：**
站在巨人的肩膀上，而不是重新发明轮子。
