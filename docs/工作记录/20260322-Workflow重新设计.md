# Workflow 创建与管理的重新设计

## 当前方案的问题

1. **Workflow 创建不够灵活**
   - 只考虑了审批场景
   - 没有考虑 ERP、数据处理等其他场景
   - 缺少自然语言创建 workflow 的能力

2. **Agent 与 Workflow 的关系不清晰**
   - 没有说明 Agent 如何选择使用哪个 workflow
   - 假设是一对一关系，但实际应该是多对多
   - 缺少 LLM 动态选择 workflow 的机制

## 重新设计的方案

### 1. Workflow 创建方式

**方式 A：自然语言创建（推荐，AI 辅助）**

```
用户输入自然语言描述：
```

### 2. Agent 与 Workflow 的关系

**核心设计：Agent 可以关联多个 Workflow，由 LLM 动态选择**

**在 Agent 配置中：**

```

├─────────────────────────────────────────────────┤

│                                                  │
│ ☑ 请假审批流程（标准流程）                       │

│                                                  │
│ ☑ 请假审批流程（高管版）                         │
```

**LLM 动态选择 Workflow 的机制：**

```
当 Agent 接收到任务时：

1. 获取该 Agent 关联的所有 Workflow
2. 如果配置了规则选择：
   - 按规则匹配，选择对应的 workflow
3. 如果配置了自动选择：
   - 将所有 workflow 的自然语言描述提供给 LLM
   - LLM 根据当前任务上下文，选择最合适的 workflow
4. 执行选中的 workflow
```

**示例：LLM 选择 Workflow**

```
System Prompt:

   描述：紧急情况下的快速审批流程，病假≤1天自动通过。

当前任务：

请假类型：年假
请假天数：3天

请选择合适的 workflow 并说明理由。

LLM 回复：
选择：请假审批流程（高管版）
理由：用户是高管，应使用简化流程。
```

```
│   ├── 报销审批
│   └── 采购审批
├── ERP 类
│   ├── 库存盘点流程
│   ├── 订单处理流程
│   └── 供应商对账流程
├── 数据处理类
│   ├── 数据清洗流程
│   ├── 报表生成流程
│   └── 数据同步流程
└── 客户服务类
    ├── 客户跟进流程
    ├── 投诉处理流程
    └── 售后服务流程
```

**每种类型的 Workflow 有不同的节点：**

```
审批类节点：
- 查询待办
- 判断条件
- 自动审批
- 人工审批
- 通知

ERP 类节点：
- 查询库存
- 更新库存
- 创建订单
- 调用外部 API
- 数据校验

数据处理类节点：
- 读取数据
- 数据转换
- 数据验证
- 写入数据
- 错误处理
```

### 4. 完整的用户体验流程

**场景 1：创建新 Workflow**

1. 用户进入"业务场景配置" → "创建 Workflow"
2. 输入自然语言描述
3. 点击"生成流程图"，AI 生成可视化流程
4. 用户查看流程图，如果不满意：
   - 修改自然语言描述，重新生成
   - 或者切换到可视化编辑器手动调整
5. 确认后保存，系统自动生成 OpenFang workflow JSON

**场景 2：Agent 使用 Workflow**

1. 管理员配置 Agent，关联多个 Workflow
2. 配置选择策略（规则选择 or 自动选择）
3. 用户触发任务
4. Agent 根据策略选择合适的 workflow 执行
5. 执行过程中，如果需要人工介入，按 workflow 定义的规则处理

**场景 3：修改现有 Workflow**

1. 用户进入 Workflow 列表，选择要修改的 workflow
2. 看到原来的自然语言描述和流程图
3. 修改自然语言描述
4. 重新生成流程图
5. 保存新版本（支持版本管理）

### 5. 技术实现要点

**自然语言生成 Workflow：**

```python
# 伪代码
def generate_workflow_from_nl(natural_language_desc: str) -> dict:
    """
    使用 LLM 将自然语言转换为 workflow JSON
    """
    prompt = f"""
    将以下自然语言描述转换为 OpenFang workflow JSON：

    {natural_language_desc}

    可用的节点类型：
    - query_tasks: 查询任务
    - condition: 条件判断
    - auto_approve: 自动审批
    - wait_for_approval: 等待人工审批
    - notify: 发送通知
    - call_api: 调用 API
    - loop: 循环
    - parallel: 并行执行

    输出格式：OpenFang workflow JSON
    """

    workflow_json = llm.generate(prompt)
    return workflow_json
```

**LLM 选择 Workflow：**

```python
def select_workflow(agent_id: int, task_context: dict) -> int:
    """
    根据任务上下文，选择合适的 workflow
    """
    # 获取 Agent 关联的所有 workflow
    workflows = get_agent_workflows(agent_id)

    # 如果只有一个，直接返回
    if len(workflows) == 1:
        return workflows[0].id

    # 如果配置了规则选择
    if agent.selection_mode == 'rule':
        return select_by_rule(workflows, task_context)

    # 如果配置了自动选择，使用 LLM
    if agent.selection_mode == 'auto':
        workflow_descriptions = [
            f"{w.id}. {w.name}\n描述：{w.natural_language_desc}"
            for w in workflows
        ]

        prompt = f"""
        当前任务上下文：
        {json.dumps(task_context, ensure_ascii=False)}

        可用的 workflow：
        {'\n\n'.join(workflow_descriptions)}

        请选择最合适的 workflow ID，只返回数字。
        """

        selected_id = llm.generate(prompt)
        return int(selected_id)
```

### 7. 总结

**核心改进：**

1. **自然语言创建 Workflow**
   - 用户用自然语言描述流程
   - AI 自动生成可视化流程图
   - 保存自然语言描述，方便后续修改

2. **Agent 与 Workflow 多对多**
   - 一个 Agent 可以关联多个 Workflow
   - 支持规则选择和 AI 自动选择
   - 灵活应对不同场景

3. **Workflow 不限于审批**
   - 支持 ERP、数据处理、客户服务等多种场景
   - 不同类型有不同的节点库
   - 可扩展性强

**这样设计的好处：**
- ✅ 降低 Workflow 创建门槛（自然语言）
- ✅ 提高 Agent 灵活性（多 Workflow）
- ✅ 支持更多业务场景（不限审批）
- ✅ 保持用户友好（隐藏技术细节）
