# AgentX 验收标准（详细版）

**文档版本：** v1.0
**创建时间：** 2026-03-22
**目的：** 提供明确、可测试的验收标准，避免模糊描述

---

## Phase A：降低复杂度

### 功能验收标准

#### AC-A1: Agent 列表页面

**测试步骤：**
1. 访问 `/agentx/agent/list`
2. 页面在 2 秒内加载完成
3. 显示 Agent 卡片列表

**验收条件：**
- [ ] 每个卡片显示：头像、名称、描述、状态、所属部门
- [ ] 支持搜索（输入名称后 500ms 内响应）
- [ ] 支持筛选（按状态、部门、模板类型）
- [ ] 分页每页 12 条，翻页响应 < 500ms
- [ ] 点击卡片跳转到详情页
- [ ] 有"创建 Agent"按钮，点击进入创建向导

**测试数据：**
- 准备 50 个 Agent 记录
- 包含不同状态（激活/停用）
- 包含不同部门

---

#### AC-A2: 创建 Agent 向导 - 步骤 1（基本信息）

**测试步骤：**
1. 点击"创建 Agent"
2. 进入步骤 1

**验收条件：**
- [ ] 表单包含字段：
  - 员工名称（必填，2-50 字）
  - 员工描述（必填，10-500 字）
  - 所属部门（必填，下拉选择）
  - 头像（可选，支持上传或选择预设）
- [ ] 名称重复时显示错误提示
- [ ] 所有必填项为空时"下一步"按钮禁用
- [ ] 填写完整后"下一步"按钮可点击
- [ ] 点击"下一步"进入步骤 2，耗时 < 200ms

**测试用例：**
```
用例 1：正常创建
- 名称：请假审批助手
- 描述：自动处理员工请假申请
- 部门：行政部
- 预期：成功进入步骤 2

用例 2：名称重复
- 名称：已存在的 Agent 名称
- 预期：显示"名称已存在"错误

用例 3：必填项为空
- 名称：空
- 预期："下一步"按钮禁用
```

- [ ] 选中模板后高亮显示
- [ ] 选中后"下一步"按钮可点击
- [ ] 点击"上一步"返回步骤 1，数据保留

**测试用例：**
```
用例 1：选择预设模板
- 选择：请假审批助手
- 预期：模板高亮，进入步骤 3 时自动勾选相关能力

用例 2：选择自定义
- 选择：自定义
- 预期：进入步骤 3 时所有能力未勾选
```

#### AC-A4: 创建 Agent 向导 - 步骤 3（配置能力）

**验收条件：**
- [ ] 能力按分类展示（至少 3 个分类）：
  - 审批管理（4 个能力）
  - 数据查询（3 个能力）
  - 通知能力（3 个能力）
- [ ] 每个能力显示：名称、描述、是否启用
- [ ] 支持勾选/取消勾选
- [ ] 如果选择了预设模板，相关能力已勾选
- [ ] 至少勾选 1 个能力才能进入下一步
- [ ] 点击"上一步"返回步骤 2，勾选状态保留

**测试用例：**
```
用例 1：使用模板默认能力
- 前置：步骤 2 选择"请假审批助手"
- 预期：审批管理相关能力已勾选

用例 2：自定义能力
- 勾选：查看待审批任务、审批请假申请
- 预期：可以进入步骤 4

用例 3：未勾选任何能力
- 预期："下一步"按钮禁用
```

#### AC-A5: 创建 Agent 向导 - 步骤 4（关联流程）

**验收条件：**
- [ ] 显示"从流程库选择"按钮
- [ ] 点击后弹出流程选择对话框
- [ ] 对话框显示 Flowable 流程列表（分页，每页 10 条）
- [ ] 每个流程显示：名称、版本、创建时间
- [ ] 支持多选（checkbox）
- [ ] 点击流程名称可预览流程图（弹出新窗口）
- [ ] 流程图加载时间 < 3 秒
- [ ] 选择后显示已选流程列表
- [ ] 配置流程选择策略：
  - 单选：规则选择 / AI 自动选择
  - 如果选择"规则选择"，显示规则配置界面
- [ ] 规则配置支持添加/删除规则
- [ ] 每条规则包含：条件 + 目标流程
- [ ] 至少关联 1 个流程才能进入下一步

**测试用例：**
```
用例 1：选择单个流程
- 选择：请假审批流程（标准）
- 策略：AI 自动选择
- 预期：成功进入步骤 5

用例 2：选择多个流程 + 规则
- 选择：请假审批流程（标准）、请假审批流程（高管版）
- 策略：规则选择
- 规则 1：用户角色 = 高管 → 高管版
- 规则 2：其他 → 标准版
- 预期：规则保存成功，进入步骤 5

用例 3：未选择流程
- 预期："下一步"按钮禁用

用例 4：预览流程图
- 点击流程名称
- 预期：弹出窗口显示流程图，图片清晰可见
```

#### AC-A6: 创建 Agent 向导 - 步骤 5（预览与激活）

**验收条件：**
- [ ] 显示配置摘要：
  - 基本信息（名称、描述、部门）
  - 使用的模板
  - 已启用的能力（列表）
  - 关联的流程（列表）
  - 流程选择策略
- [ ] 有"保存草稿"按钮
- [ ] 有"激活并发布"按钮
- [ ] 点击"保存草稿"：
  - 保存到数据库，状态 = 草稿
  - 显示成功提示
  - 跳转到 Agent 列表
  - 耗时 < 2 秒
- [ ] 点击"激活并发布"：
  - 保存到数据库，状态 = 激活
  - 后台自动执行（生成 agent_key、注册到 OpenFang）
  - 显示成功提示
  - 跳转到 Agent 详情页
  - 总耗时 < 5 秒

**测试用例：**
```
用例 1：保存草稿
- 点击"保存草稿"
- 预期：
  - 数据库有记录，status = 0
  - 跳转到列表页
  - 列表中显示该 Agent，状态为"草稿"

用例 2：激活并发布
- 点击"激活并发布"
- 预期：
  - 数据库有记录，status = 1
  - agent_key 已生成（UUID 格式）
  - agentx_agent_process 表有关联记录
  - agentx_agent_capability 表有能力记录
  - 跳转到详情页
  - 详情页显示"已激活"状态
```

#### AC-A8: 后台自动化处理

**验收条件：**
- [ ] 创建 Agent 时自动生成 agent_key（UUID 格式）
- [ ] 自动创建流程关联记录（agentx_agent_process 表）
- [ ] 自动创建能力记录（agentx_agent_capability 表）
- [ ] 如果配置了 OpenFang，自动注册（调用 OpenFang API）
- [ ] 所有操作在事务中执行（失败全部回滚）
- [ ] 失败时有清晰的错误提示

**测试用例：**
```
用例 1：正常创建
- 创建 Agent
- 预期：
  - agentx_agent 表有 1 条记录
  - agentx_agent_process 表有 N 条记录（N = 关联流程数）
  - agentx_agent_capability 表有 M 条记录（M = 启用能力数）
  - agent_key 格式正确（UUID）

用例 2：OpenFang 注册失败
- Mock OpenFang API 返回 500
- 预期：
  - 创建失败
  - 数据库无记录（事务回滚）
  - 显示错误："注册到 OpenFang 失败，请稍后重试"
```

## Phase B：身份与渠道

### 功能验收标准

#### AC-B1: 渠道配置页面

**测试步骤：**
1. 访问 `/agentx/channel/config`
2. 点击"添加渠道"

**验收条件：**
- [ ] 支持 3 种渠道类型：Telegram、企业微信、钉钉
- [ ] Telegram 配置包含：
  - Bot Token（必填，加密存储）
  - 关联的 Agent（多选）
  - 访问控制（单选：所有员工/指定部门/指定人员）
- [ ] 有"测试连接"按钮
- [ ] 测试连接成功显示："✓ 连接成功"
- [ ] 测试连接失败显示具体错误信息
- [ ] 保存后自动同步到 OpenFang

**测试用例：**
```
用例 1：配置 Telegram Bot

- 关联 Agent：请假审批助手、报销审批助手
- 访问控制：指定部门 → 行政部

- 预期：显示"✓ 连接成功"
- 点击"保存"
- 预期：
  - agentx_channel_config 表有记录
  - config 字段包含加密的 token
  - agent_ids 字段包含 2 个 Agent ID

用例 2：Token 错误
- Bot Token：invalid_token
- 点击"测试连接"
- 预期：显示"✗ 连接失败：Token 无效"
```

#### AC-B2: 用户绑定流程

**测试步骤：**
1. 用户在 Telegram 发送消息给 Bot
2. Bot 检测到未绑定用户
3. Bot 返回绑定链接

**验收条件：**
- [ ] 绑定链接格式：`https://oa.company.com/agentx/bind?token={jwt}`
- [ ] Token 包含信息：channel_type, channel_user_id, channel_username
- [ ] Token 10 分钟有效
- [ ] 点击链接跳转到 OA 登录页（未登录）
- [ ] 登录后自动完成绑定
- [ ] 显示绑定成功页面
- [ ] 绑定记录永久有效

**测试用例：**
```
用例 1：首次绑定
- Telegram 用户 ID：123456789
- 点击绑定链接
- 登录 OA（用户：张三）
- 预期：
  - agentx_user_channel_binding 表有记录
  - user_id = 张三的 ID
  - channel_user_id = 123456789
  - status = 1
  - 显示："✓ 绑定成功！现在可以返回 Telegram 继续对话"

用例 2：Token 过期
- 生成绑定链接
- 等待 11 分钟
- 点击链接
- 预期：显示"绑定链接已过期，请重新获取"

用例 3：重复绑定
- 已绑定的用户再次点击绑定链接
- 预期：显示"您已绑定，无需重复操作"
```

#### AC-B3: 角色解析服务

**验收条件：**
- [ ] 支持 7 种角色类型：
  1. direct_manager（直属上级）
  2. department_head（部门负责人）
  3. department_vp（部门副总）
  4. hr_manager（HR 经理）
  5. finance_approver（财务审批人）
  6. fixed_role（固定角色）
  7. custom_role（自定义角色）
- [ ] 查询响应时间 < 100ms（有缓存）
- [ ] 查询响应时间 < 500ms（无缓存）
- [ ] 缓存有效期 5 分钟
- [ ] 找不到审批人时返回默认审批人（可配置）

**测试用例：**
```
用例 1：解析直属上级
- 输入：roleType = "direct_manager", userId = 张三的 ID
- 预期：返回 [李四的 ID]（李四是张三的直属上级）

用例 2：解析部门负责人
- 输入：roleType = "department_head", deptId = 行政部 ID
- 预期：返回 [王五的 ID]（王五是行政部负责人）

用例 3：找不到审批人
- 输入：roleType = "direct_manager", userId = CEO 的 ID
- 预期：返回 [默认审批人 ID]

用例 4：缓存测试
- 第 1 次查询：耗时 300ms
- 第 2 次查询（5 分钟内）：耗时 < 100ms
- 第 3 次查询（6 分钟后）：耗时 300ms
```

## Phase C：扩展能力

### 功能验收标准

#### AC-C1: Flowable 扩展节点 - AI 决策节点

**验收条件：**
- [ ] 可以在 Flowable 设计器中拖拽使用
- [ ] 配置界面包含：
  - Prompt 模板（必填，支持变量）
  - 输入变量（多选）
  - 超时时间（默认 30 秒）
  - 输出变量名（默认 aiDecision）
- [ ] 执行时调用 LLM
- [ ] 超时后抛出异常（不卡死流程）
- [ ] 结果保存到流程变量

**测试用例：**
```
用例 1：正常执行
- Prompt："根据请假天数判断是否需要审批：${leaveDays}"
- 输入变量：leaveDays = 3
- 预期：
  - 调用 LLM
  - 返回结果（如："需要审批"）
  - 流程变量 aiDecision = "需要审批"
  - 执行时间 < 30 秒

用例 2：超时
- Mock LLM 响应时间 > 30 秒
- 预期：
  - 抛出 TimeoutException
  - 流程进入异常处理分支
```

## 总结

**文档特点：**
- 每个验收标准都有明确的测试步骤
- 包含具体的测试用例和预期结果
- 有量化的性能指标
- 可以直接用于测试

**使用方式：**
- 开发完成后，按照验收标准逐项测试
- 所有条件通过才算验收合格
- 测试用例可以转化为自动化测试脚本
